# Проверка Family VPN на физическом телефоне — 03.10.2026

Исторический отчёт для **0.1.0.4**. Позднее тимлид разрешил стабильный выпуск
0.1.0.5 после собственной проверки; исправление и новые результаты описаны
в TEST_PLAN.md. Ниже результаты исходной сессии не переписаны задним числом.

**Решение: 0.1.0.4 не готова к стабильному выпуску.** Подтверждено падение
при применении обхода приложений с активным VPN. Помимо исправления этого
дефекта, остаются проверки полного обновления и длительной работы.

## Сборка и условия

- Samsung SM-S948B, Android 16 / API 36, ARM64; физический телефон пользователя.
- Установленная подписанная release: `com.familyvpn.android`, версия `0.1.0.4`,
  versionCode `5`, не debuggable.
- SHA256 установленной APK совпал с локальной
  `app/build/distribution/0.1.0.4/FamilyVPN-0.1.0.4-arm64.apk`:
  `1dc2e455b549792337a78a37971e1db078b23d1483ce6fb4c769b60e500f1a3b`.
- Для независимой проверки сети временно установлен отдельный минимальный
  `com.familyvpn.qa`: INTERNET / ACCESS_NETWORK_STATE, без доступа к профилю
  Family VPN. Старый instrumentation-harness на телефоне не запускался.
- IP сравнивались по SHA256 в памяти пробника; реальные IP, адрес портала,
  credentials, содержимое профиля и UUID в этот отчёт не включены.
- Код приложения, VPS и публичные релизы в рамках проверки не изменялись.

## Блокирующий дефект

1. Подключить VPN.
2. Открыть настройки → Обход приложений.
3. Выбрать дополнительное приложение и нажать «Применить».

**Фактически:** вместо подтверждения переподключения приложение падает;
VPN отключается. Новое исключение не сохраняется; прежний список остаётся.
После повторного открытия приложение можно подключить вручную.

В crash-buffer телефона для текущей 0.1.0.4:

```text
10-03 00:46:41.479  FATAL EXCEPTION: main
Process: com.familyvpn.android
android.view.WindowManager$BadTokenException:
Unable to add window -- token null is not valid; is your activity running?
at android.app.AlertDialog$Builder.show
at com.familyvpn.poc.SettingsActivity.render$lambda$22(SettingsActivity.kt:145)
```

В обработчике используется `AlertDialog.Builder(ui.context)`.
`UiKit.context` создан поверх `AppPreferences.localized(activity)` через
`createConfigurationContext`, а не непосредственно поверх Activity.
Нужно обеспечить Activity-контекст с корректным window token для диалога,
сохранив выбранную тему и язык. После исправления повторно проверить
подтверждение, отмену и сохранность профиля при переподключении.

| Сценарий | Результат на телефоне |

| Маскирование и глазик | Пароль скрыт по умолчанию; показ и повторное скрытие проверены на тестовом значении |

| Пинг | HTTPS-задержка обновляется нажатием; наблюдались значения 274–671 мс; без VPN — «—» |
| Мобильная сеть | DNS и HTTPS 204 проходят из отдельного приложения; внешний IPv4 отличается от прямого подключения |

| Смена сети и потеря связи | При отключении обеих сетей пинг «Недоступно», профиль сохранён, VPN остаётся запущенным; после возврата мобильной сети DNS и HTTPS восстановились |
| Обход при выключенном VPN | Выбор → Apply → подключение: пробник выходит напрямую, внешний IPv4 совпадает с прямой контрольной проверкой |

| Короткий сон | Экран выключен примерно 115 секунд; процесс VPN сохранился, после пробуждения пробник подтвердил DNS/HTTPS и исходный VPN IPv4 |
| Разрешение уведомлений | Проверены отказ, повторный запрос и разрешение; начальное состояние разрешения восстановлено |
| Проверка обновлений | Ручная проверка сообщает об отсутствии более новой совместимой стабильной версии |
| Суточное задание | Job 2401 зарегистрирован как periodic 24h / persisted / required network; принудительный запуск принят системой |

Зафиксированные сетевые контрольные случаи:
`mobile_vpn_on`, `mobile_direct_after_crash`, `mobile_app_bypass`,
`mobile_restored_full_vpn`, `wifi_attempt`, `mobile_after_network_loss`,
`mobile_after_short_sleep`.
Хеш IPv4 при bypass равен прямому контрольному хешу; после снятия исключения,
на Wi-Fi и после потери сети равен исходному VPN-хешу.

## Что остаётся открытым

- Полный цикл Update: обнаружение настоящей новой стабильной версии,
  уведомление один раз, открытие Update, загрузка/отмена, системная установка,
  отказ от установки и сохранность профиля после обновления.
  Подходящего нового опубликованного релиза нет; искусственный stable не создавался.
- Сутки работы, длительный сон/Doze, ограничения аккумулятора Samsung,
  восстановление после reboot и реальные сутки работы задания.
- IPv6: на прямом мобильном подключении полноценный IPv6 также не доступен.
  Успешная проверка отсутствия утечек на сети с рабочим IPv6 не получена.
- Маршрут DNS и отсутствие DNS-утечек отдельно не доказаны; успешное DNS-разрешение
  означает доступность, а не определяет маршрут запросов.
- Сравнение с Hiddify, прикладные операции в конкретном банковском приложении,
  импорт другого локального JSON и потеря процесса в этой сессии не проверялись.

## Завершение проверки

Тестовое исключение снято при выключенном VPN; исходное единственное
исключение сохранено. Отдельное приложение-пробник удалено, собственный
временный XML на телефоне удалён. Профиль восстановлен после повторного входа,
VPN снова подключён, мобильная передача данных включена, Wi-Fi выключен
(как до теста). Интерфейс возвращён к русскому языку и тёмному оформлению.
Начальный режим выбора темы не фиксировался: тёмное оформление восстановлено,
полное совпадение режима «системная/тёмная» не утверждается.
Уведомления снова имеют исходное состояние: разрешение не выдано.
Чтобы получать будущие уведомления, пользователь должен разрешить их в настройках.
Временные файлы ввода учётных данных удалены; plaintext-пароль не сохранялся
в тестовых артефактах. Логи пользователя, старые VPN-приложения и бэкапы не удалялись.

## Условия допуска к выпуску

Исправить подтверждённый дефект диалога, повторить Apply с активным VPN
(подтверждение и отмена), завершить проверки Update и длительного поведения.
Одна успешная сессия на одном телефоне не закрывает оставшиеся сценарии.
Публикация, деплой и коммит не выполнялись.
