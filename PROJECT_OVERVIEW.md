# Family VPN — обзор проекта

> Состояние локального репозитория на 30 сентября 2026 года. Этот файл не
> подтверждает, что все локальные изменения развёрнуты на VPS. Секреты,
> ссылки подписок и рабочие VPN-конфигурации здесь не хранятся.

## Назначение

Family VPN — личный VPN для семьи (около 10 человек) на собственном VPS.
Пользователи получают доступ и конфигурации через портал; администратор
управляет клиентами, оплатой и состоянием сервиса. Это не публичный
коммерческий VPN. Второй VPS предусмотрен архитектурой, но пока не куплен.

## Как устроен работающий сервис

| Компонент | Ответственность |
| --- | --- |
| Xray под управлением 3X-UI | VPN-трафик по VLESS + Reality через `443/tcp` |
| 3X-UI | Управление inbound и клиентами; панель доступна только на `127.0.0.1` через SSH-туннель |
| nginx | Внешний вход к веб-порталу по пути `/portal/` |
| FastAPI-портал | Вход пользователей, выдача QR/ссылок/конфигураций, HTML-админка и Telegram Mini App API; сам слушает `127.0.0.1:3180` |
| Telegram-бот | Пользовательские запросы об оплате, административные команды и уведомления; работает в режиме polling внутри портала |
| systemd-таймеры | Биллинг, проверка здоровья сервисов и резервное копирование |

VPN-трафик идёт от клиентского приложения непосредственно к Xray. Портал
выдаёт параметры доступа и выполняет административные операции, но не
проксирует пользовательский VPN-трафик. Данные 3X-UI читаются через
`xui_db.py`, изменения клиентов проходят через `xui_admin.py`; вручную
редактировать `x-ui.db` нельзя.

## Биллинг и административные интерфейсы

Политика оплаты и журнал административных действий хранятся в
`TelegramStore`, а не в 3X-UI. Telegram Mini App/Admin API и команды бота
используют `AdminService` с идемпотентностью операций. HTML-маршрут
`/portal/admin/billing` пока остаётся отдельным legacy-путём и вызывает
`XuiAdmin` напрямую. Его унификация с `AdminService` — открытый
архитектурный вопрос, а не выполненная миграция.

## Собственный клиент: текущий этап

В `android-poc/` находится экспериментальное Android-приложение на Kotlin
с встроенным sing-box 1.14.2, `VpnService`, входом через портал,
защищённым хранением собственного профиля, импортом локального JSON и
кнопками подключения/отключения. Это первый сетевой gate проекта
собственного клиента, **не** семейный релиз и **не** замена Hiddify.

Экспорт Hiddify на тестовом телефоне содержит только VLESS outbound.
Android PoC дополняет его экспериментальными TUN/DNS/route-настройками в
памяти; это не доказанная копия фактической runtime-конфигурации Hiddify.
HTTPS API входа и выдачи собственного профиля развёрнут на VPS. На телефоне
проверены вход и короткие подключения по Wi-Fi/5G с выходом через VPS,
а также переключение Wi-Fi → 5G без аварии. Исправлены авария IPv6 и
видимость полей входа на Android 16. Длительная устойчивость, сон и полная
сравнительная матрица ещё не подтверждены. Пока этот gate не
закрыт, полноценные Android-функции, Windows-клиент и iOS не считаются
начатыми. Плановый порядок: Android → Windows → iOS.

Рабочий JSON и credentials не должны попадать в Git, APK или
диагностические отчёты. Подробности сборки и ограничений — в
[`android-poc/README.md`](android-poc/README.md).

## Границы безопасности и работы

- Не раскрывать пароли, токены, Reality-ключи, VLESS-ссылки, QR-коды,
  subscription-токены и рабочие конфигурации.
- Не открывать панель 3X-UI наружу; она остаётся на localhost. Не менять
  `limitIp` и не обновлять Xray/3X-UI без отдельного согласования.
- Не менять работающий VPS, firewall или systemd-сервисы без явного
  подтверждения владельца. Локальный код не считать автоматически
  развёрнутым.
- Сохранять существующие незакоммиченные изменения. Не записывать в
  `docs/context/` без явного `yes` владельца.
- При работе над собственным клиентом не удалять рабочий профиль Hiddify:
  он остаётся способом восстановить доступ после теста.
