## 2. Контекст проекта (кратко)

- **Цель:** управляемый VPN для семьи (~10 человек) на собственном VPS.

- **Стек:** Ubuntu 24.04, 3X-UI + Xray (VLESS Reality, порт 443), FastAPI портал (127.0.0.1:3180), nginx (прокси `/portal/`), Telegram-бот для биллинга и уведомлений.

- **Ключевые пути на VPS:**

  - `/etc/x-ui/x-ui.db` — БД 3X-UI (клиенты, inbounds)

  - `/etc/family-portal/config.yaml` — конфиг портала (секреты, пользователи)

  - `/opt/family-portal/` — код портала (venv)

  - `/var/lib/family-portal/` — SQLite для бота и визитов

  - `/var/log/x-ui/access.log` — лог для статистики

  - `/var/backups/family-vpn/` — бэкапы

- **Деплой:** Git-репозиторий на Windows `C:\Users\Huawei\Desktop\VPN`), SCP на VPS, ручное копирование с поправкой прав.

- **Документация:** `docs/stages/` — пошаговые инструкции, `README.md` — индекс.

## 3. Общие правила взаимодействия

1. **Все изменения, влияющие на работающую систему (VPS), требуют явного подтверждения пользователя.**

   Не предлагай выполнять команды `sudo`, `systemctl`, `ufw`, `iptables`, перезагрузку сервисов без явного запроса или без согласия. Если команда необходима, опиши её и спроси «Выполнить?».

2. **Никогда не выводи в чат реальные секреты:** пароли, токены бота, приватные ключи Reality, SSH-ключи, `session_secret`, `x-ui` логин/пароль.

   Вместо этого используй плейсхолдеры: `<your-bot-token>`, `<secret>` или ссылайся на файлы конфигурации на VPS.

3. **При работе с 3X-UI помни: панель должна слушать только `127.0.0.1`** — никогда не предлагай открывать её наружу.

4. **Перед предложением git-коммита:** покажи дифф (изменения) и спроси «Сделать коммит? (yes/no)».

   Если пользователь сказал «да» — формируй осмысленное сообщение коммита на русском или английском (по желанию пользователя).

5. **Все команды и пути давай в формате, подходящем для окружения:**

   - Для VPS — bash, `sudo -u family-portal` где нужно.

   - Для Windows — PowerShell (если локально).

6. **Фокус на задаче. Не делай лишнего!**

   - Если пользователь просит поправить конкретную функцию — **меняй только её**. Не трогай другие функции, даже если они кажутся «тоже плохими».

   - Не предлагай рефакторинг целого модуля, если он не является частью задачи.

   - Не анализируй и не комментируй код, который не относится к вопросу.

   - Если задача сформулирована слишком широко («помоги с биллингом»), уточни: «Какую именно часть биллинга нужно доработать? Опиши границы».

   - **Генерируй код только для указанного файла/функции.** Если нужно затронуть соседний файл (например, добавить импорт) — явно спроси разрешения.

   - Если видишь, что для решения задачи требуется изменение в другом модуле — скажи об этом, но не пиши код для него без команды.

## 4. Правила работы с кодом портала `portal/`)

### 4.1. Структура модулей (запоминай)

- `main.py` — FastAPI приложение, lifespan, маршруты.

- `config.py` — загрузка `config.yaml` в датаклассы.

- `auth.py` — авторизация, куки, подписки.

- `xui_db.py` — **read-only** доступ к `x-ui.db`.

- `xui_admin.py` — **write** операции (продление, отключение, сброс expiry).

- `vless.py` — генерация ссылок.

- `visit_log.py` — парсинг access.log, агрегация.

- `telegram_store.py` — SQLite для бота.

- `telegram_bot.py` — логика бота (polling).

- `telegram_notify.py` — уведомления через HTTP (для cron).

- `billing_cron.py` — автоматические напоминания и отключения.

- `health_monitor.py` — проверка сервисов.

### 4.2. Стиль кода

- Следуй PEP 8.

- Используй аннотации типов.

- Логируй важные действия через `logging` (уровень INFO для событий, WARNING для проблем).

- Для работы с SQLite используй параметризованные запросы (безопасность).

- Файлы с конфиденциальными данными (например, `config.yaml`) не должны попадать в репозиторий — используй `.example` файлы.

### 4.3. Тестирование

- При изменении логики (биллинг, парсинг логов) предложи написать или обновить тесты (pytest).

- Для ручной проверки используй `smoke-test.sh` и `health_monitor --test-alert`.

### 4.4. Локальность изменений (дополнение к п.3.6)

- Если нужно изменить функцию, **приводи только её новый код** (или дифф), а не весь файл.

- Если изменение затрагивает сигнатуру функции (аргументы, возврат) — обнови и вызовы этой функции внутри **того же файла**, но не трогай другие файлы, где она может использоваться, пока пользователь явно не попросит.

- Если ты добавляешь новую зависимость (импорт), сначала убедись, что она уже есть в `requirements.txt`; если нет — сообщи и спроси, нужно ли добавить.

## 5. Правила деплоя и обновления на VPS

1. **Обновление одного файла:**

   - SCP файла во `/tmp/`.

   - Копирование `sudo cp /tmp/... /opt/family-portal/app/...`.

   - Смена владельца: `sudo chown family-portal:family-portal ...`.

   - Права: `chmod u=rw,go= ...` (для py-файлов).

   - Перезапуск сервиса: `sudo systemctl restart family-portal`.

   - Проверка статуса и логов.

2. **Полная установка портала** — используй `scripts/05-family-portal.sh` (только при первоначальной настройке).

3. **При деплое помни:** типичная ошибка — неправильные права на `/opt/family-portal/app` (владелец root или vpnadmin). Всегда исправляй на `family-portal:family-portal`.

4. **После изменения конфига** `/etc/family-portal/config.yaml`) — перезапускай портал.

5. **При работе с systemd** используй файлы из `scripts/systemd/`; не меняй их вручную на VPS без согласования.

## 6. Биллинг и управление клиентами

- **Политика оплаты** хранится в `billing_policy` (таблица `telegram_store`), а не в 3X-UI.

- При включении «Требовать оплату» — вызывай `xui_admin.expire_client_now()` (expiry = текущее время).

- При подтверждении оплаты — `xui_admin.extend_client()` на 30 дней и сброс `requires_payment = False`.

- **Автоматический cron** `family-billing.timer`) обрабатывает напоминания и отключения.

- **Не предлагай** вручную править `x-ui.db` через SQLite — только через функции `xui_admin.py`.

## 7. Работа с Telegram-ботом

- Бот работает в режиме **polling** внутри lifespan FastAPI.

- Администраторы заданы в `config.yaml` `admin_chat_ids`).

- Команды бота для админов: `/who`, `/pay`, `/free`, `/extend`, `/admin`.

- При изменении логики бота обязательно проверяй, что кнопки `ReplyKeyboardMarkup` и `InlineKeyboard`) работают корректно.

## 8. Мониторинг и бэкапы

- `family-health.timer` (каждую минуту) — проверяет `x-ui`, портал и порт 443.

- При двух последовательных сбоях — шлёт алерт в Telegram, при восстановлении — тоже.

- `family-backup.timer` (ежедневно в 04:30) — архивирует БД, конфиги, сертификаты.

- Off-site бэкап на Windows — через `pull-backup.ps1` (запускается планировщиком).

## 10. Запрещённые действия (красная зона)

- **Никогда не изменяй `limitIp` в 3X-UI** — это вызывает массовые отключения.

- **Не предлагай открыть порт панели 3X-UI наружу** (она всегда [localhost](http://localhost)).

- **Не публикуй vless-ссылки, QR-коды или subscription-токены в чат** — это приватные данные.

- **Не удаляй и не перезаписывай бэкапы без явной команды.**

- **Не обновляй Xray-core или 3X-UI без согласования** — могут сломаться настройки Reality.

## 11. Формат команд и примеров

Все примеры должны быть самодостаточными и безопасными.

Для секретов используй переменные окружения или указывай, что они берутся из `config.yaml`.

Пример хорошего ответа:

> Для продления клиента user05 на 30 дней выполните на VPS:

> ```bash

> sudo -u family-portal FAMILY_PORTAL_CONFIG=/etc/family-portal/config.yaml \

>   /opt/family-portal/venv/bin/python -c "from app.xui_admin import extend_client; extend_client('user05', 30)"

> ```

> После этого перезапустите портал: `sudo systemctl restart family-portal`.
